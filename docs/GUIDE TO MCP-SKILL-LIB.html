Bắt đầuGetting started

Tổng quanOverview

mcp-skill-lib là cầu nối skill giữa mọi agent MCP trên máy bạn (Claude Code, Codex, OpenCode, Copilot...). Bạn không gọi tool trực tiếp — chỉ cần nói với agent bằng lời thường, nó tự chọn đúng tool trong số 9 tool phía dưới.mcp-skill-lib is the knowledge bridge between every MCP agent on your machine (Claude Code, Codex, OpenCode, Copilot...). You never call a tool directly — just tell your agent in plain language, and it picks the right one of the 9 tools below.

Khái niệm chínhKey concepts

  • MCP server — phần mềm cầu nối giữa agent AI và một khả năng cụ thể bên ngoài mô hình; ở đây là quản lý skill.the bridge software between an AI agent and a specific outside capability — here, managing skills.
  • SkillSkill — một thư mục chứa SKILL.md, dạy agent cách làm đúng 1 việc cụ thể.a folder containing SKILL.md that teaches an agent how to do one specific job.
  • Thư viện skillSkill library (~/.skill-library) — nơi lưu skill cục bộ trên máy bạn, dùng chung cho mọi agent đã đăng ký.where skills are stored locally on your machine, shared by every registered agent.
  • gh CLI — công cụ dòng lệnh GitHub dùng để xác thực. Không có token nào được lưu trong dự án này.the GitHub command-line tool used for authentication. No token of any kind is stored by this project.
  • Benchmark — quy trình 6 lớp kiểm chứng chất lượng 1 skill bằng bằng chứng thật, trước khi chia sẻ nó lên repo chung.the 6-layer process that verifies a skill's quality with real evidence before it's shared to the common repo.

Install and register the "mcp-skill-lib" MCP server
(@aidev3-web/mcp-skill-library) for yourself on this machine. Do this:

1. Check `node --version` is 18 or higher. If Node.js is missing or too
   old, tell me how to install/upgrade it and stop.

2. Check whether "mcp-skill-lib" is already registered for you, at any
   scope (e.g. `claude mcp list` / `claude mcp get mcp-skill-lib` for
   Claude Code, or the equivalent config file for your agent type). If
   it already exists:
   - Show me exactly what it's currently pointing at (command, scope)
     instead of silently adding a second one.
   - Do NOT register a duplicate under the same name at a different
     scope — that creates an ambiguous, conflicting setup. Ask me
     whether to leave the existing one alone, fix it in place, or
     remove it before you add a new one.
   - Only continue to the steps below if there is truly nothing
     registered yet, or I've told you to replace what's there.

3. Check whether the GitHub CLI is installed and logged in:
   `gh --version` (install from https://cli.github.com/ if missing), then
   `gh auth status` (if not logged in, tell me to run `gh auth login` and
   wait for me to confirm it succeeded before continuing). This server
   reads no token of any kind — it shells out to `gh` for every GitHub
   call, using whichever account `gh` is logged in as. If `gh auth status`
   shows more than one logged-in account, ask me which one is actually a
   collaborator on the target repo(s), and run `gh auth switch` to make
   that one active before continuing — don't assume the currently
   "active" account is the right one. Do NOT ask me which repo(s) I want
   to use right now — that's decided later, per search/pull call, not
   during install. Just note for later: a private repo needs me to
   already be a collaborator on it (`gh auth login` alone doesn't grant
   that).

4. Identify which agent you are:
   - Claude Code CLI → use `claude mcp add`.
   - Claude Desktop → edit claude_desktop_config.json.
   - OpenCode → edit opencode.json.
   - Codex CLI → edit ~/.codex/config.toml.
   - Antigravity IDE (Google's agentic IDE — NOT Gemini CLI, even though it
     uses a `~/.gemini` folder for its own config) → edit
     `~/.gemini/config/mcp_config.json` (global) or `.agents/mcp_config.json`
     (workspace-only), or use the UI: **...** at the top of the Agent panel →
     **MCP Servers** → **Manage MCP Servers** → **View raw config**.

5. Before registering, ask me which scope I want: `--scope user` (registers
   it for me, available in every project on this machine) or
   `--scope project` (only in the current project folder). Do not default
   to either one silently — wait for my answer, then use the exact
   command/config snippet for your agent type from this repo's README.md
   ("Register with your agent" section) with the scope I picked. Prefer
   the recommended
   local-run install: `git clone https://github.com/aidev3-web/mcp-skill-library.git`
   (or reuse an existing checkout if I already have one), `npm install`, then point your
   config at that checkout's `index.js` via `node`. Only fall back to
   the `npx` alternative if I explicitly say I'd rather not manage a
   local checkout. No `env` block or token of any kind is needed in
   either case. If the checkout's path contains spaces (common on
   Windows, e.g. under a folder with non-English characters), quote the
   whole path in the command.

6. Always use the default SKILL_LIBRARY_PATH (~/.skill-library) — do not
   ask me about this or add an `env` block for it.

7. Tell me to restart you (or reload MCP servers) so the new config
   is picked up.

8. Once restarted, call the `detect_agents` tool once and
   report back which agent locations were found on this machine, to
   confirm the server is actually running.

Tham khảoReference

benchmark_skill chấm chất lượng như thế nàoHow benchmark_skill actually scores quality

6 lớp, mỗi lớp đo đúng 1 việc — Layer 1-3 bắt buộc bằng chứng thật từ session mới, không chấp nhận agent tự đoán điểm.6 layers, each measuring exactly one thing — Layers 1-3 require real evidence from fresh sessions, a guessed score is not accepted.

0 · TĩnhStatic

Máy tự tính: độ dài mô tả, từ ngữ mơ hồ, số file phụ trợ. Không cần chạy thử.Computed mechanically: description length, vague wording, module count. No execution needed.

1 · Trigger

Mở session mới thật, thử 1 câu nên trigger + 1 câu không nên trigger, quan sát thật. Chặn nếu câu nên trigger không fire, hoặc câu không nên lại fire.Spawns a fresh real session, tests 1 prompt that should fire it + 1 that shouldn't, observes real behavior. Blocks if the should-fire prompt doesn't, or the shouldn't-fire prompt does.

2 · Kết quảOutcome

Mở 2 session thật cùng 1 việc: 1 có skill, 1 không có. So sánh chất lượng thật. Chặn nếu skill không giúp ích hơn.Spawns 2 real sessions on the same task: 1 with the skill, 1 without. Compares real quality. Blocks if the skill didn't help.

3 · Ổn địnhStability

Chạy cùng 1 kịch bản 3 lần thật (3 session), so sánh có giống nhau không. Chặn nếu <3 lần hoặc không nhất quán.Runs the same scenario 3 real times (3 sessions), compares consistency. Blocks if under 3 runs or inconsistent.

4 · Edge case & guardrail

Đọc SKILL.md và chấm 0-20 — có nêu rõ giới hạn/trường hợp đặc biệt không. Không cần chạy thử.Reads SKILL.md and scores 0-20 — does it call out its own limits/edge cases. No execution needed.

5 · Đúng phạm viScope

Đọc SKILL.md và chấm 0-20 — phạm vi có gọn, không lấn việc khác không. Không cần chạy thử.Reads SKILL.md and scores 0-20 — is the job narrowly bounded, no scope creep. No execution needed.

Vì server này không tự mở được session (không có khả năng gọi agent), benchmark_skill chỉ tính được Layer 0 — với Layer 1-3, nó trả về 1 "kế hoạch test" và giao lại cho chính agent đang chat (có khả năng mở session mới qua công cụ riêng của nó) thực thi thật, rồi báo kết quả cụ thể lại cho push_skill. push_skill kiểm tra từng field bằng chứng riêng (fire đúng/sai, có giúp ích không, có nhất quán không) — 1 tổng điểm cao không che được 1 lớp bị fail cụ thể. Because this server can't spawn sessions itself (no agent-orchestration capability), benchmark_skill only computes Layer 0 — for Layers 1-3, it returns a test plan and hands execution to the calling agent (which does have its own session-spawning tooling), which reports concrete results back to push_skill. push_skill checks each evidence field individually (fired correctly or not, actually helped or not, consistent or not) — a high total score can't paper over one specific failed layer.

Gọi 2 lần: lần 1 chỉ có skillPath → nhận kế hoạch test ở trên. Sau khi thực thi xong cả 6 lớp, gọi lại lần 2 với skillPath + results → server ghi ra 1 file <tên-skill>.benchmark-report.html nằm cạnh thư mục skill (không nằm trong, để không vô tình bị push lên), chứa bảng đầy đủ 6 lớp + bằng chứng thật + xác nhận pass/fail tổng thể — lưu lại được, mở lại xem sau này. Called twice: call 1 with just skillPath → returns the test plan above. Once all 6 layers are done, call again with skillPath + results → the server writes a <skill-name>.benchmark-report.html file next to the skill folder (not inside it, so it never gets pushed), containing the full 6-layer table + real evidence + an overall pass/fail verdict — a permanent, reopenable record.

Lưu ý & sự cố có thể xảy raNotes & possible issues

1. Repo private không đọc được1. Private repo can't be read

Nguyên nhânCause Account gh chưa là collaborator trên repoThe gh account isn't a collaborator on the repo
Xử lýFix Kiểm tra gh auth status, nhờ admin thêm collaboratorCheck gh auth status, ask an admin to add you as collaborator

2. Server báo CONNECTION_CLOSED2. Server reports CONNECTION_CLOSED

Nguyên nhânCause Sai đường dẫn index.js hoặc chưa npm installWrong index.js path or npm install not run
Xử lýFix Kiểm tra lại path, chạy lại npm installRecheck the path, rerun npm install

3. Token GitHub cũ gây lỗi3. A stale GitHub token causes errors

Nguyên nhânCause GITHUB_TOKEN/GH_TOKEN cũ còn trong env, ưu tiên hơn gh loginAn old GITHUB_TOKEN/GH_TOKEN in the env takes priority over the gh login session
Xử lýFix Unset biến môi trường đó trước khi dùngUnset that env var before using the server

4. remove_skill không xóa được source4. remove_skill can't delete the source

Nguyên nhânCause Còn agent/scope khác đang symlink tới skill đóAnother agent/scope still symlinks to that skill
Xử lýFix Bỏ filter scopes/targets để gỡ hết, hoặc xóa tayDrop the scopes/targets filter to remove them all, or delete by hand
