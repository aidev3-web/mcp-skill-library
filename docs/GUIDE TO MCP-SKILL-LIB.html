Bắt đầuGetting started

Tổng quanOverview

mcp-skill-lib là cầu nối skill giữa mọi agent MCP trên máy bạn (Claude Code, Codex, OpenCode, Copilot...). Bạn không gọi tool trực tiếp — chỉ cần nói với agent bằng lời thường, nó tự chọn đúng tool trong số 10 tool phía dưới.mcp-skill-lib is the knowledge bridge between every MCP agent on your machine (Claude Code, Codex, OpenCode, Copilot...). You never call a tool directly — just tell your agent in plain language, and it picks the right one of the 10 tools below.

Khái niệm chínhKey concepts

  • MCP server — phần mềm cầu nối giữa agent AI và một khả năng cụ thể bên ngoài mô hình; ở đây là quản lý skill.the bridge software between an AI agent and a specific outside capability — here, managing skills.
  • SkillSkill — một thư mục chứa SKILL.md, dạy agent cách làm đúng 1 việc cụ thể.a folder containing SKILL.md that teaches an agent how to do one specific job.
  • Thư viện skillSkill library (~/.skill-library) — nơi lưu skill cục bộ trên máy bạn, dùng chung cho mọi agent đã đăng ký.where skills are stored locally on your machine, shared by every registered agent.
  • gh CLI — công cụ dòng lệnh GitHub dùng để xác thực. Không có token nào được lưu trong dự án này.the GitHub command-line tool used for authentication. No token of any kind is stored by this project.
  • Benchmark — quy trình 6 lớp kiểm chứng chất lượng 1 skill bằng bằng chứng thật, trước khi chia sẻ nó lên repo chung.the 6-layer process that verifies a skill's quality with real evidence before it's shared to the common repo.

Install and register the "mcp-skill-lib" MCP server
(@aidev3-web/mcp-skill-library) for yourself on this machine. Do this:

1. Check `node --version` is 18 or higher. If Node.js is missing or too
   old, tell me how to install/upgrade it and stop.

2. Check whether "mcp-skill-lib" is already registered for you, at any
   scope (e.g. `claude mcp list` / `claude mcp get mcp-skill-lib` for
   Claude Code, or the equivalent config file for your agent type). If
   it already exists:
   - Show me exactly what it's currently pointing at (command, scope)
     instead of silently adding a second one.
   - Do NOT register a duplicate under the same name at a different
     scope — that creates an ambiguous, conflicting setup. Ask me
     whether to leave the existing one alone, fix it in place, or
     remove it before you add a new one.
   - Only continue to the steps below if there is truly nothing
     registered yet, or I've told you to replace what's there.

3. Check whether the GitHub CLI is installed and logged in:
   `gh --version` (install from https://cli.github.com/ if missing), then
   `gh auth status` (if not logged in, tell me to run `gh auth login` and
   wait for me to confirm it succeeded before continuing). This server
   reads no token of any kind — it shells out to `gh` for every GitHub
   call, using whichever account `gh` is logged in as. If `gh auth status`
   shows more than one logged-in account, ask me which one is actually a
   collaborator on the target repo(s), and run `gh auth switch` to make
   that one active before continuing — don't assume the currently
   "active" account is the right one. Do NOT ask me which repo(s) I want
   to use right now — that's decided later, per search/pull call, not
   during install. Just note for later: a private repo needs me to
   already be a collaborator on it (`gh auth login` alone doesn't grant
   that).

4. Identify which agent you are:
   - Claude Code CLI → use `claude mcp add`.
   - Claude Desktop → edit claude_desktop_config.json.
   - OpenCode → edit opencode.json.
   - Codex CLI → edit ~/.codex/config.toml.
   - Antigravity IDE (Google's agentic IDE — NOT Gemini CLI, even though it
     uses a `~/.gemini` folder for its own config) → edit
     `~/.gemini/config/mcp_config.json` (global) or `.agents/mcp_config.json`
     (workspace-only), or use the UI: **...** at the top of the Agent panel →
     **MCP Servers** → **Manage MCP Servers** → **View raw config**.

5. Before registering, ask me which scope I want: `--scope user` (registers
   it for me, available in every project on this machine) or
   `--scope project` (only in the current project folder). Do not default
   to either one silently — wait for my answer, then use the exact
   command/config snippet for your agent type from this repo's README.md
   ("Register with your agent" section) with the scope I picked. Prefer
   the recommended
   local-run install: `git clone https://github.com/aidev3-web/mcp-skill-library.git`
   (or reuse an existing checkout if I already have one), `npm install`, then point your
   config at that checkout's `index.js` via `node`. Only fall back to
   the `npx` alternative if I explicitly say I'd rather not manage a
   local checkout. No `env` block or token of any kind is needed in
   either case. If the checkout's path contains spaces (common on
   Windows, e.g. under a folder with non-English characters), quote the
   whole path in the command.

6. Always use the default SKILL_LIBRARY_PATH (~/.skill-library) — do not
   ask me about this or add an `env` block for it.

7. Tell me to restart you (or reload MCP servers) so the new config
   is picked up.

8. Once restarted, call the `detect_agents` tool once and
   report back which agent locations were found on this machine, to
   confirm the server is actually running.

search_remote_skillsTìm trong 1 repo đã biếtSearch one known repo
VàoIn: owner, repo, ref?, query?, limit, cursor?RaOut: items[], totalMatched, nextCursor
  1. Lấy cây file của repo (qua gh) — nếu đã tải trong 5 phút gần đây thì dùng lại từ cache, không gọi mạng lại.Load the repo's file tree via gh — reused from a 5-minute in-memory cache if already fetched, no repeat network call.
  2. Lọc ra mọi file SKILL.md trong cây đó (chính là danh sách skill).Filter that tree down to every SKILL.md blob (that's the skill list).
  3. Nếu có query: giữ lại thư mục nào có đường dẫn chứa chuỗi đó (không phân biệt hoa/thường) — so khớp trên tên thư mục, chưa đọc nội dung file.If query is set: keep only folders whose path contains that substring (case-insensitive) — matched on the folder path, no file content read yet.
  4. Cắt trang theo limit/cursor, rồi mới tải nội dung SKILL.md của đúng trang đó để lấy name/description từ frontmatter.Slice the page by limit/cursor, then fetch that page's SKILL.md content to read name/description from frontmatter.
  5. Trả về danh sách kèm nextCursor nếu còn trang sau.Returns the list plus a nextCursor if more pages remain.
search_all_sourcesTìm trên mọi repo trong sources.jsonSearch every repo in sources.json
VàoIn: query?, limitRaOut: items[] (kèm source), sourcesSearched[]
  1. Đọc danh sách repo từ sources.json (chung, sửa qua PR) + sources.local.json (riêng, để trong SKILL_LIBRARY_PATH, không commit).Reads the repo list from sources.json (shared, edited via PR) + sources.local.json (personal, lives in SKILL_LIBRARY_PATH, never committed).
  2. Lượt 1: chỉ tải cây file của từng repo, lọc theo query trên đường dẫn — repo nào lỗi thì ghi nhận lỗi và bỏ qua, không làm hỏng cả lượt tìm.Pass 1: loads just each repo's tree, filters by query on the path — a repo that errors is recorded and skipped, not fatal to the whole search.
  3. Lượt 2: chỉ tải nội dung SKILL.md cho đúng số kết quả nằm trong limit — không tải tất cả rồi vứt, vì 1 lần tìm rỗng trên nhiều repo lớn có thể ra hàng trăm kết quả.Pass 2: only fetches SKILL.md content for rows that made it inside limit — not fetch-everything-then-discard, since an empty query across a few big repos can be hundreds of matches.
  4. Gộp kết quả từ mọi repo thành 1 danh sách, mỗi dòng có kèm repo nguồn.Merges results from every repo into one list, each row tagged with its source repo.
find_skillsTìm theo ngữ nghĩa trên toàn hệ sinh tháiSemantic search across the whole ecosystem
VàoIn: query, limit, resolveDetails?RaOut: items[] (kèm installs), searchType, unresolved[]
  1. Khi nào dùng: chỉ khi search_all_sources không ra gì. Tool đó chỉ thấy các repo trong sources.json; tool này với tới cả hệ sinh thái skill mở.When to use: only after search_all_sources comes up empty. That one only sees repos in sources.json; this reaches the whole open skill ecosystem.
  2. Chặn sớm nếu query ngắn hơn 2 ký tự — registry tự từ chối, nên dừng tại chỗ thay vì để lộ một lỗi 400 khó hiểu từ dịch vụ ngoài.Blocks early if query is under 2 characters — the registry rejects those itself, so it fails here rather than surfacing an opaque 400 from a remote service.
  3. Gọi skills.sh — kho đăng ký đứng sau CLI mã nguồn mở npx skills của Vercel Labs. Endpoint /api/search công khai, không cần token nào, đúng quy tắc "không lưu credential" của dự án.Calls skills.sh — the registry behind Vercel Labs' open-source npx skills CLI. Its /api/search endpoint is public and needs no token, which is what makes it fit this project's no-credentials rule.
  4. Ngữ nghĩa, không phải từ khoá. Truy vấn nhiều từ được khớp theo nghĩa (searchType: "semantic"); một từ đơn rơi về khớp mờ theo tên ("fuzzy"). Vì vậy hãy viết truy vấn thành một câu mô tả công việc — hỏi "over-engineering" vẫn tìm ra skill tự gọi mình là "scope creep".Semantic, not keyword. A multi-word query is matched by meaning (searchType: "semantic"); a single word falls back to fuzzy name matching ("fuzzy"). So phrase the query as a sentence describing the job — asking for "over-engineering" still finds a skill that calls itself "scope creep".
  5. Số lượt cài là độ phổ biến, KHÔNG phải kiểm duyệt. Chính skills.sh cũng ghi vậy. Một skill nhiều lượt cài chỉ có nghĩa nhiều người tải — vẫn phải chạy validate_skill + benchmark_skill trước khi dùng.Install counts are popularity, NOT review. skills.sh says so itself. A high count only means many people downloaded it — still run validate_skill + benchmark_skill before using it.
  6. Tra ngược GitHub (bỏ qua được bằng resolveDetails: false): registry chỉ trả owner/repo/skillId, thiếu đường dẫn thật và mô tả. Tool tải cây thư mục một lần cho mỗi repo (dùng lại cache 5 phút) để lấp hai trường đó, nhờ vậy kết quả đưa thẳng sang pull_skill được.Resolves details on GitHub (skippable via resolveDetails: false): the registry returns only owner/repo/skillId — no real folder path, no description. The tool loads one cached repo tree per repo (not one call per hit) to fill both in, so a result can be handed straight to pull_skill.
  7. Kết quả không tra được (repo riêng tư, đã đổi tên, thư mục không trùng tên skill) không bị vứt bỏ — vẫn trả về với path: null và được liệt kê trong unresolved[].Hits that can't be resolved (private repo, renamed, folder not named after the skill) are not dropped — they come back with path: null and are listed in unresolved[].
  8. Đây là tool duy nhất phụ thuộc dịch vụ ngoài. /api/search không nằm trong tài liệu API chính thức của skills.sh (bản /api/v1/* cần token Vercel và trả 401), nên nó có thể đổi hoặc biến mất. Mọi kiểu hỏng — thêm auth, endpoint bị gỡ trả về HTML, mất mạng, treo — đều báo lỗi rõ ràng kèm nhắc dùng search_all_sources, không bao giờ crash. Đổi nguồn bằng biến SKILLS_REGISTRY_URL.This is the only tool with an external dependency. /api/search is not in skills.sh's published API docs (the /api/v1/* ones need a Vercel token and answer 401), so it may change or disappear. Every failure mode — auth added, endpoint retired and answering HTML, host unreachable, request hung — surfaces as a clear message pointing at search_all_sources, never a crash. Redirect it with SKILLS_REGISTRY_URL.
  9. Kiểm upstream trước khi kéo về. Skill phổ biến thường được lập chỉ mục dưới repo phát hành lại chứ không phải repo gốc, và bản sao có thể không có license dù bản gốc là MIT. Nếu frontmatter ghi upstream, hãy lấy từ đó.Check for an upstream before pulling. Popular skills are often indexed under a redistributor rather than their origin, and the copy may carry no license even when the original is MIT. If the frontmatter names an upstream, pull from there instead.
pull_skillKéo skill về thư viện localFetch a skill into the local library
VàoIn: owner, repo, ref?, skillPaths[]RaOut: pulled[] (status, localPath, warnings)
  1. Với mỗi skillPath: kiểm tra repo có đúng file SKILL.md ở đường dẫn đó không — không có thì báo lỗi ngay, không tải gì.For each skillPath: checks the repo actually has a SKILL.md at that path — if not, errors immediately, nothing downloaded.
  2. Chặn tên thư mục đích không hợp lệ (chứa /, .., đường dẫn tuyệt đối...) — không cho ghi ra ngoài thư viện skill.Refuses an unsafe destination folder name (containing /, .., an absolute path...) — never writes outside the skill library.
  3. Với từng file trong skill: nếu đường dẫn file trong repo trỏ ra ngoài thư mục đích (zip-slip) thì huỷ toàn bộ skill đó, không ghi file nào.Per file inside the skill: if the repo's path for that file resolves outside the destination folder (zip-slip), the whole skill is aborted — nothing written.
  4. Ghi từng file xuống SKILL-LIB/<tên-skill>/ dưới dạng byte thô (không qua text) — để không làm hỏng ảnh/PDF/font trong skill.Writes each file into SKILL-LIB/<skill-name>/ as raw bytes (not text) — so images/PDFs/fonts inside the skill aren't corrupted.
  5. Đọc lại frontmatter vừa tải, cảnh báo nếu thiếu name/description, tên không khớp thư mục, hoặc có key riêng của 1 agent cụ thể khó mang sang agent khác.Re-reads the just-downloaded frontmatter, warns if name/description is missing, the name doesn't match the folder, or there are agent-specific keys that won't port cleanly.
detect_agentsDò agent nào có mặt trên máyDetect which agents are present
VàoIn: cwd?RaOut: agents[] (agent, scope, skillsDir, agentPresent)
  1. Không gọi mạng — chỉ kiểm tra ổ đĩa cục bộ.No network call — checks the local disk only.
  2. Với mỗi agent đã biết (Claude Code, Codex, OpenCode, Cursor, Gemini CLI, Copilot): kiểm tra cả 2 thư mục skill khả dĩ — global (thư mục home) và project (thư mục cwd).For each known agent (Claude Code, Codex, OpenCode, Cursor, Gemini CLI, Copilot): checks both its possible skill folders — global (home directory) and project (the cwd folder).
  3. Trả về danh sách đầy đủ mọi vị trí đã kiểm tra, kèm cờ có mặt/không — không chỉ đếm số lượng, để agent gọi biết chính xác thiếu chỗ nào.Returns every location it checked with a present/absent flag — not just a count, so the calling agent knows exactly which ones are missing.
deploy_skillSymlink skill vào từng agentSymlink the skill into each agent
VàoIn: skillName, targets?, scopes?RaOut: results[] (agent, scope, status)
  1. Kiểm tra SKILL-LIB/<skillName>/SKILL.md tồn tại — chưa có thì báo chạy pull_skill trước.Checks SKILL-LIB/<skillName>/SKILL.md exists — if not, tells you to run pull_skill first.
  2. Chạy detect_agents nội bộ, rồi lọc theo targets/scopes nếu có — agent gọi tool phải hỏi bạn chọn scope trước (global hay project), không tự mặc định cài hết mọi nơi.Runs detect_agents internally, then filters by targets/scopes if given — the calling agent is required to ask you which scope (global or project) first, never silently deploy everywhere.
  3. Tạo symlink (junction trên Windows) từ thư mục skill agent đó tới đúng skill trong SKILL-LIB/ — chỉ 1 bản gốc, mọi agent trỏ vào cùng chỗ.Creates a symlink (junction on Windows) from that agent's skill folder to the one copy in SKILL-LIB/ — a single source of truth every agent points at.
  4. Không bao giờ ghi đè 1 thư mục thật (không phải symlink) đã có sẵn cùng tên — báo lỗi thay vì xoá dữ liệu người dùng.Never overwrites an existing real folder (not a symlink) with the same name — errors instead of clobbering user data.
  5. Máy không hỗ trợ symlink thì tự chuyển sang copy file thường, và báo rõ trong kết quả đây là bản sao chứ không phải symlink.Falls back to a plain file copy where symlinking isn't available, and flags in the result that it's a copy, not a symlink.
remove_skillGỡ symlink & dọn thư việnUndo the deploy & clean up the library

If you already own a same-named repo that is not a fork of this upstream, it refuses ("fork-name-conflict") rather than committing into the wrong project.

A new branch starts from upstream's head, not the fork's — so a stale fork doesn't drag unrelated diff into the PR. An existing branch is built on top of, which is what adds a commit to its open PR.
  7. Bước 5-7 — Commit vào fork: tạo 1 commit duy nhất, nguyên tử, qua Git Data API (mọi lệnh ghi đều nhắm vào fork, không bao giờ vào upstream) (blob từng file → tree → commit → cập nhật ref), kèm 1 file .meta.json ghi ai đăng/ai sửa/khi nào — cập nhật skill cũ thì giữ nguyên uploadedBy/uploadedAt gốc.Steps 5-7 — Commit into the fork: builds one atomic commit via the Git Data API (every write targets the fork, never upstream) (blob per file → tree → commit → ref update), plus a .meta.json recording who uploaded/updated and when — updating an existing skill preserves the original uploadedBy/uploadedAt.
  8. Bước cuối — Chống ghi đè: ngay trước khi cập nhật ref, kiểm tra lại nhánh trong fork có bị push đè trong lúc chờ không — có thì huỷ, báo "conflict", không mất dữ liệu của người kia, bảo thử lại nguyên lệnh.Final step — Race guard: right before updating the ref, re-checks whether the branch in the fork moved underneath it while this push was running — if so, aborts with "conflict", doesn't clobber the other person's write, and tells you to retry the whole call.
  9. Bước 8 — Mở PR: tự mở pull request từ <fork>:skill/<tên> về nhánh mặc định của upstream, kèm điểm benchmark và người nộp. Nếu skill đó đã có PR đang mở thì không mở PR mới — commit vừa rồi tự nằm trong PR cũ (pullRequestAction: "updated"). Commit được đẩy lên fork trước khi mở PR, nên bước PR hỏng cũng không mất skill: kết quả kèm sẵn câu lệnh gh pr create để làm tay. Người bảo trì upstream review và merge — tool không bao giờ tự merge.Step 8 — Open the PR: opens a pull request from <fork>:skill/<name> to upstream's default branch, carrying the benchmark score and submitter. If that skill already has an open PR, no duplicate is opened — the commit lands in the existing one (pullRequestAction: "updated"). The commit reaches the fork before the PR step, so a PR failure never loses the skill: the result carries the exact gh pr create command to finish by hand. An upstream maintainer reviews and merges — the tool never self-merges.

benchmark_skill chấm chất lượng như thế nàoHow benchmark_skill actually scores quality

6 lớp, mỗi lớp đo đúng 1 việc — Layer 1-3 bắt buộc bằng chứng thật từ session mới, không chấp nhận agent tự đoán điểm.6 layers, each measuring exactly one thing — Layers 1-3 require real evidence from fresh sessions, a guessed score is not accepted.

0 · TĩnhStatic

Máy tự tính: độ dài mô tả, từ ngữ mơ hồ, số file phụ trợ. Không cần chạy thử.Computed mechanically: description length, vague wording, module count. No execution needed.

1 · Trigger

Mở session mới thật, thử 1 câu nên trigger + 1 câu không nên trigger, quan sát thật. Chặn nếu câu nên trigger không fire, hoặc câu không nên lại fire.Spawns a fresh real session, tests 1 prompt that should fire it + 1 that shouldn't, observes real behavior. Blocks if the should-fire prompt doesn't, or the shouldn't-fire prompt does.

2 · Kết quảOutcome

Mở 2 session thật cùng 1 việc: 1 có skill, 1 không có. So sánh chất lượng thật. Chặn nếu skill không giúp ích hơn.Spawns 2 real sessions on the same task: 1 with the skill, 1 without. Compares real quality. Blocks if the skill didn't help.

3 · Ổn địnhStability

Chạy cùng 1 kịch bản 3 lần thật (3 session), so sánh có giống nhau không. Chặn nếu <3 lần hoặc không nhất quán.Runs the same scenario 3 real times (3 sessions), compares consistency. Blocks if under 3 runs or inconsistent.

4 · Edge case & guardrail

Đọc SKILL.md và chấm 0-20 — có nêu rõ giới hạn/trường hợp đặc biệt không. Không cần chạy thử.Reads SKILL.md and scores 0-20 — does it call out its own limits/edge cases. No execution needed.

5 · Đúng phạm viScope

Đọc SKILL.md và chấm 0-20 — phạm vi có gọn, không lấn việc khác không. Không cần chạy thử.Reads SKILL.md and scores 0-20 — is the job narrowly bounded, no scope creep. No execution needed.

Vì server này không tự mở được session (không có khả năng gọi agent), benchmark_skill chỉ tính được Layer 0 — với Layer 1-3, nó trả về 1 "kế hoạch test" và giao lại cho chính agent đang chat (có khả năng mở session mới qua công cụ riêng của nó) thực thi thật, rồi báo kết quả cụ thể lại cho push_skill. push_skill kiểm tra từng field bằng chứng riêng (fire đúng/sai, có giúp ích không, có nhất quán không) — 1 tổng điểm cao không che được 1 lớp bị fail cụ thể. Because this server can't spawn sessions itself (no agent-orchestration capability), benchmark_skill only computes Layer 0 — for Layers 1-3, it returns a test plan and hands execution to the calling agent (which does have its own session-spawning tooling), which reports concrete results back to push_skill. push_skill checks each evidence field individually (fired correctly or not, actually helped or not, consistent or not) — a high total score can't paper over one specific failed layer.

Gọi 2 lần: lần 1 chỉ có skillPath → nhận kế hoạch test ở trên. Sau khi thực thi xong cả 6 lớp, gọi lại lần 2 với skillPath + results → server ghi ra 1 file <tên-skill>.benchmark-report.html nằm cạnh thư mục skill (không nằm trong, để không vô tình bị push lên), chứa bảng đầy đủ 6 lớp + bằng chứng thật + xác nhận pass/fail tổng thể — lưu lại được, mở lại xem sau này. Called twice: call 1 with just skillPath → returns the test plan above. Once all 6 layers are done, call again with skillPath + results → the server writes a <skill-name>.benchmark-report.html file next to the skill folder (not inside it, so it never gets pushed), containing the full 6-layer table + real evidence + an overall pass/fail verdict — a permanent, reopenable record.
